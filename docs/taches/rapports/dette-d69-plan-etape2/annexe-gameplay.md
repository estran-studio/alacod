## 6. Risques transverses (trace, parité, ordre)

- **Parité des types vides** : aucune coupe ci-dessus n'ajoute ni ne retire un type enregistré sous checksum ; les `rollback_and_trace*` listés restent dans les plugins sim d'origine, dans le même ordre. Ne **pas** déplacer `PowerUpPickup`/`PointsCredit`/`RepairPointsTracking`/`PerkMachine` (non neutres) dans un nouveau plugin placé ailleurs : leurs plugins (`PowerUpsPlugin`, `EconomyPlugin`) restent aux positions 165 et 158 de `CoreSetupPlugin::build`.
- **Ordre de schedule** : les enveloppes `Asset` (ajouts `RonAssetPlugin`) n'ont aucun effet sur `GgrsSchedule` ; les nouveaux plugins app s'ajoutent soit dans `PresentationPlugin` (présentation : interaction, blank, debug des vagues), soit juste avant le plugin sim de leur module (chargeurs RON) ; `GgrsSchedule` refuse les ambiguïtés (core.rs:128-130) : ne retirer aucun `.after/.before` listé ci-dessus.
- **Snapshots** : les remplacer par une ressource insérée à `OnEnter(GameLoading)` change **où** on lit l'asset ; pour les overrides de `scenario` (runner.rs:671-800, `Update`) la valeur doit être posée avant. Pour la hot-reload d'armes, régénérer `WeaponRegistry` (voir § 3).
- **Tests** : `effects_runtime.rs` (1170, 1217, 1295), `effects_v3.rs` (557), `powerups.rs` (603-620, 851, 921) construisent `Assets<WeaponsConfig>`/`GlobalAsset`/`PowerUpsConfig` ; à réécrire avec `WeaponRegistry`/`PowerUpsTable` quand les systèmes changent.
- **Détail `HashMap`** : `ResolvedWaveTier.enemy_probabilities: HashMap` (balance.rs:39) est parcouru **trié** (waves/systems.rs:494-495), donc déterministe ; ne pas le remplacer sans nécessité.
